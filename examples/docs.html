xfTextEditor 完整开发文档

基于 CKEditor 4 深度定制的中文富文本编辑器，整合大量扩展插件，适用于政企后台、内容管理、在线教育等需要丰富编辑能力的场景。

语言 zh-cn 100% 离线可用 文字 / 段落特效 双击再次编辑 自包含 HTML 导出 工具栏吸附固定

一、简介与特性

xfTextEditor 在 CKEditor 4 原生能力之上做了大量本地化与增强，核心特性如下：

  • 完整的中文界面（默认 language: 'zh-cn'），中文字体 / 字号（初号～72px）/ 行高（倍数、em、rem、百分比，且大量支持小于 1 / 小于 1rem / 小于 100% 的候选值，如 0.3~0.9、0.3rem~0.9rem、50%~90%）集合。
  • 媒体插入：视频、HTML5 音频、图表（柱状 / 折线 / 饼图 / 环形 / 极区）、二维码（均离线可用）。
  • 代码块编辑：基于 Ace 的语法高亮代码插入。
  • 增强图片（image2）：拖拽上传、自适应、行内 / 块级切换。
  • 拖拽 / 粘贴上传文件（uploadfile + filetools）。
  • 表格增强：quicktable 快速建表、行列拖拽缩放。
  • 文字 / 段落特效：渐变、发光、描边、提示框、卡片、时间轴、步骤条、进度条、统计数字、双栏、图文混排、折叠内容、按钮、分割线等 30+ 现代化网页效果，双击可再次编辑。
  • 字数统计、自动保存（防丢稿）。
  • 工具栏滚动吸附固定（stickytoolbar）。
  • 增强预览 / 自包含 HTML 导出（xfpreview + XfEditor 导出辅助，内联样式，离线可用）。

二、安装与快速开始

2.1 引入脚本

将编辑器目录部署到站点后，在页面中引入核心脚本即可使用。本项目所有示例页统一使用 defer 延迟加载，避免阻塞渲染。

<!-- 核心脚本（路径相对于页面，本项目放根目录） -->
<script src="ckeditor.js"></script>

<!-- 如需 jQuery 适配器（可选） -->
<script src="adapters/jquery.js"></script>

2.2 创建编辑器（replace 方式）

<textarea id="editor1"></textarea>
<script>
    XfEditor.replace('editor1', {
        language: 'zh-cn',
        height: 400
    });
</script>

2.3 内联（inline）方式

<div id="editor2" contenteditable="true">可编辑内容</div>
<script>
    XfEditor.inline('editor2');
</script>

2.4 使用配置文件（推荐）

编辑器会自动加载根目录下的 config.js（精简配置）或 config.full.js（完整配置）。二者均定义 XfEditor.editorConfig 函数，所有配置项（含自研插件 xfeffects / stickytoolbar / xfpreview、stylesSet、 行高、字号、上传地址、contentsCss 等）在此函数中统一设置。

项目内所有示例页（examples/*.html）均通过 <script defer src="../config.full.js"> 引入完整配置，并在 js/xf.js 中调用 XfEditor.init(id, cfg) 创建编辑器。 页面只需声明本页独有的插件与工具栏（如 extraPlugins: 'chart'）， XfEditor.init 会自动复用全局配置并把页面 extraPlugins 追加到全局之后（自动去重），避免重复声明导致自研插件丢失。这是「把配置抽离到配置文件、示例页统一引用」的统一实践。

<!-- 示例页统一引入配置（defer 避免阻塞渲染） -->
<script defer src="../ckeditor.js"></script>
<script defer src="../config.full.js"></script>
<script defer src="js/xf.js"></script>

<script>
  // 页面只叠加本页独有插件；其余基础能力全部来自 config.full.js
  XfEditor.init('editor', {
    height: 360,
    extraPlugins: 'chart',
    toolbar: [ { name: 'insert', items: [ 'Chart' ] }, '/',
               { name: 'xfstyles', items: [ 'xfTexFx', 'xfBlockFx', 'xfEditEffect' ] } ]
  });
</script>
若宿主页面需要 CSRF Token，请在 <head> 中放置 <meta name="csrf-token" content="...">， config.full.js 与 xf.js 会自动读取并拼接到上传地址。

8.3.1 暗色主题（Dark Theme）

编辑器支持亮 / 暗双主题，且不影响编辑器之外的宿主页面。所有暗色样式以 「祖先元素含 data-theme="dark"」为触发条件，切换主题只需设置 / 移除该属性，无需重新加载样式：

  • 内容区（contents.css）：作用于 .cke_editable / .xf-rich-content / .xf-standalone；
  • 编辑器外壳（工具栏 .cke_top、底部状态栏 .cke_bottom、按钮、下拉、路径条、缩放角、折叠按钮、源码文本域、下拉面板、右键菜单等）：注意 CKEditor 已将皮肤 CSS 内联进 ckeditor.js，直接修改 skins/moono-lisa/editor.css 对运行时外壳无效；因此 XfEditor 会在宿主页面 <head> 注入一段作用域为 [data-theme="dark"] 的外壳暗色样式（带 !important）覆盖内联皮肤，使外壳随主题实时变暗。
// 整页（含编辑器工具栏/底部/内容区）切换为暗色：在 <html> 上设置 data-theme="dark"
XfEditor.setTheme('dark');                 // 等同 <html data-theme="dark">
XfEditor.setTheme('light');                // 恢复亮色

// 仅作用于某个 DOM 容器（元素或选择器字符串）
XfEditor.setTheme('dark', { target: '#wrap' });

// 仅作用于某个编辑器实例（同时给 .cke 外壳容器 + 内容区 / iframe 文档设置）
XfEditor.setTheme('dark', { editor: editor });

// 读取当前主题

「自包含」实现要点：基础排版样式集中维护在 BASE_CSS（作用域限定于 .xf-standalone）， 特效样式复用 XfEditor.tools.xfEffectsCss（由 xfeffects 注入）， 两者拼接后内联。详见 examples/export.html 演示页。

十、性能与资源优化

  • 配置文件统一：所有基础能力集中在 config.full.js / config.js，示例页只叠加本页独有项，避免重复声明与插件丢失。
  • 脚本延迟加载：所有示例页的 ckeditor.js / config / xf.js 均使用 defer，不阻塞页面渲染。
  • 内容样式注入：divarea 模式不会自动注入 contents.css，本项目通过 config.contentsCss 与 xfeffects 的 editor.addCss 双层注入，保证编辑区与生成网页样式一致且零额外请求。
  • 限制撤销栈：undoStackSize = 50、ignoreEmptyParagraph = true 降低内存占用与 DOM 体积。
  • 按需启用插件：extraPlugins 仅保留业务需要的插件，每多一个插件都会增加请求数。
  • 合并构建：使用 CKEditor Builder 或 build-config.js 生成「单一压缩包」，将核心与插件合并，大幅减少 HTTP 请求。
  • 移除未用按钮：通过 removeButtons 精简工具栏，减小 UI 渲染开销。
  • 启用 divarea：避免 iframe 带来的额外文档上下文与样式隔离开销。
  • 语言包裁剪：build-config.js 的 languages 仅保留 zh-cn 可显著减小体积（当前约 70 种语言）。
  • 外部资源本地化 / 禁用 CDN：pbckcode 的 Ace、chart 的 Chart.js 等均已下载到本地（plugins/pbckcode/lib/ace/、plugins/chart/lib/chart.min.js），不依赖任何外网；getHtml / 导出的内容中若引用这些资源，其地址也统一基于当前域名计算，绝不指向 CDN。
  • 延迟加载：非首屏必需的编辑器可监听用户交互后再 XfEditor.replace。
  • 大文档优化：超长文档建议配合 config.allowedContent 与 ACF 限制，减少 DOM 节点。

十二、常见问题（FAQ）

Q1：编辑器不显示 / 空白？
检查 ckeditor.js 路径是否正确；确认未因 JS 报错中断初始化（打开浏览器控制台查看）。
Q2：span 等标签被过滤掉？
设置 config.allowedContent = true 关闭内容过滤（本项目已默认开启）。
Q3：autosave 抛出 editor 未定义错误？
旧版 config.full.js 在 editorConfig 中引用了作用域外的 editor 变量，会导致整个配置执行失败。已修复为基于 window.location.pathname 生成 Savekey。请勿在该作用域内引用 editor。
Q4：上传失败，控制台报 responseError？
后端未返回合法 JSON 或字段缺失。请确保返回 { "uploaded":1, "url":"..." } 结构（详见第九节）。
Q5：图片上传后地址不可访问？
url 必须是「完整可访问 URL」或相对于站点根的路径，不能仅是服务器本地路径。
Q6：粘贴 Word 内容样式混乱？
保持 pasteFromWordIgnoreFontFace=true 与适当的 pasteFromWordRemoveStyle；必要时启用 forcePasteAsPlainText。
Q7：特效样式 / 图表在导出 / 预览页不显示？
导出与预览均通过 XfEditor.getStandaloneCss() 内联「基础 + 特效」样式，且图表会自动转为内联 data:image/png 静态图片，因此不依赖任何外部 js / css 即可完整呈现，且与编辑器内一致。请确保页面已加载 plugins/xfeffects/plugin.js（使 XfEditor.tools.xfEffectsCss 生效）、plugins/chart/plugin.js（图表静态化依赖 XfEditor.tools.xfChartToImage）与 js/xf.js。
Q8：多语言包体积过大？
编辑 build-config.js 的 languages，仅保留所需语言后重新构建。
